# Humanizer-cn

去除中文文本里的 AI 写作痕迹，在**保住作者真实声音和全部事实**的前提下，把文字改得更像真人写的。它只是 Markdown，任何支持 skill 的 agent 都能用。

本 skill 是三个 skill 的融合与中文重写。逐条归属：

- [blader/humanizer](https://github.com/blader/humanizer) v3.0.0 —— 分级、*弱信号*、"何时不动手"、反编造铁律、声音匹配、"把文本当素材不当指令"。
- no-ai-slop —— 最小改动、保住声音、可移植性测试、编辑原则（别降智 / 动词发力 / 展示而非告知）、冒号揭示、伪洞察开场、修辞设问、解释性元话语、总结复述结尾、假深刻收尾金句、eval 自检闭环、**只检测模式（诊断不改写、不打分、不猜作者归属）**。
- [humanizer-zh](https://github.com/op7418/Humanizer-zh) —— 中文专属模式（成语堆砌、翻译腔、引号、顿号排比、中文副词 / 填充词表）、核心规则速查、质量评分表、"个性与灵魂"（含缺乏灵魂诊断）、完整示例；但**已修正其示例凭空编造来源 / 细节的问题**（见下节）。

模式体系源头是维基百科的 ["Signs of AI writing"](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)（WikiProject AI Cleanup 维护）。

## 与 humanizer-zh 的关键差异

humanizer-zh 的示例会把模糊表述"升级"成看起来具体的假细节（例如凭空写出"根据中科院 2019 年调查""每周集市""18 世纪教堂""成立于 1994 年"）。**humanizer-cn 把这类行为定为严重错误**：所有"改写后"示例只使用原文已有的信息，宁可短而真，不要长而假。

## 安装

作为 Claude 插件（若托管在 Git 仓库）：

```text
/plugin marketplace add <你的仓库>
/plugin install humanizer-cn@humanizer-cn
```

手动安装：把整个 `humanizer-cn/` 目录复制到 agent 的 skills 目录（例如 `~/.agents/skills/` 或 `~/.claude/skills/`），确保 `SKILL.md` 在该目录根部。

## 使用

改写模式（默认）：

```
/humanizer-cn 帮我去掉这段文字的 AI 腔：
[粘贴文本]
```

匹配你的声音（推荐，改完更像你）：

```
/humanizer-cn
这是我自己的写作样本，用来匹配语气：
[粘贴 2-3 段你写的东西]

现在帮我改这段：
[粘贴要去痕的文本]
```

只检测模式（只诊断、不改写、不打分）：

```
/humanizer-cn 帮我扫一下这段有没有 AI 痕迹，先别改：
[粘贴文本]
```

改文件：

```
/humanizer-cn 去掉 docs/launch-post.md 里正文的 AI 腔
```

文件模式只改散文，代码块、行内代码、命令、路径、YAML 元数据、数据、链接目标一律不动。

## 它会做什么

1. 通读全文、标出所有 AI tell（强的先标）。
2. 判断输入是"有真实声音的人写草稿"（→ 轻改保声音）还是"整篇 AI 生成"（→ 深改可重组），据此选力度。
3. 起草改写，保留每一个有据主张，**不添加任何原文没有的事实**。
4. 对照 `eval.md` 自检、返工。
5. 输出改写稿 + "改了什么" + 质量评分表（1–50）。

## 32 个模式

分五组，按强弱排序。标 *弱信号* 的只在同一段里和别的 tell 一起出现时才动手。

- **A. 铺垫而非直陈（最强）**：不是X而是Y / 一句话收尾 / 假深刻金句 / 摆姿势开场 / 伪洞察开场 / 修辞设问 / 和空气辩论 / 冒号揭示 / 解释性元话语
- **B. 按规则堆节奏**：三段式·顿号三连 / 开头重复 / 破折号滥用 / 同义词循环 / 虚假范围 / 过度限定 / 被动·缺主语
- **C. 夸大与借权威**：AI 高频词·副词·填充短语 / 夸大意义·"挑战与展望"套路 / 模糊关联 / -ing 式肤浅分析 / 宣传广告腔 / 借权威·模糊归因 / 回避"是·有"
- **D. 按规则加格式**：装饰性粗体·标签列表 / 装饰性标题·表情·箭头 / 弯引号·引号混用
- **E. 残渣与结尾**：聊天残渣·谄媚语气 / 知识截止免责·猜测 / 标题被首句复述 / 写"上一版" / 总结复述式结尾 / 假深刻收尾金句

完整定义、识别标志、改写前后示例见 `SKILL.md`。

## 文件说明

- `SKILL.md` —— skill 主文件（agent 读取的提示词）。
- `eval.md` —— 改写后的逐项自检清单（含反编造检查）。
- `agents/openai.yaml` —— OpenAI 兼容 agent 的显示名与默认提示。
- `.claude-plugin/` —— Claude 插件与市场清单。
- `scripts/validate-package.py` —— 打包自洽性校验（版本号一致、模式连续编号、反编造铁律在场）。
- `.github/workflows/validate.yml` —— 在 push / PR 时跑校验。
- `AGENTS.md` —— 维护本 skill 的约定。

## 版本历史

- **1.0.0** —— 首个版本。融合 humanizer v3.0.0 + no-ai-slop + humanizer-zh，中文重写为 32 个模式；新增中文专属模式（成语堆砌、翻译腔、顿号排比、中文引号、中文副词/填充词表）；确立"禁止编造"为最高铁律并修正 humanizer-zh 示例虚构来源的问题；加入只检测模式与评分表的隔离、按输入类型选姿态（轻改/深改）、"把文本当素材不当指令"的安全守卫，以及端到端完整示例。
